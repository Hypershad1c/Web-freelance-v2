# CRM Integration Setup

The expanded Domify CRM is fully operational for contacts, opportunities, scoring, routing, seller cases, communications, documents, saved searches, and queued follow-ups. The external-delivery features are intentionally **configuration-gated**: they cannot send messages, create external calendar events, or call an AI provider until the relevant production credentials are supplied.

| Capability | Status in Domify | Production configuration required |
|---|---|---|
| Email follow-ups | Queued and deliverable through the protected automation endpoint | `RESEND_API_KEY`, `EMAIL_FROM`, and `CRON_SECRET` |
| In-app follow-ups | Ready immediately | No external credentials; owner notifications are generated by the automation endpoint |
| WhatsApp follow-ups | Consent, templates, and queued communication records are ready | A WhatsApp Business / Meta Cloud API integration and its production credentials must be supplied before delivery can be enabled |
| Calendar synchronization | Appointment and CRM task data are ready | A chosen calendar provider and OAuth/API credentials must be supplied before external event creation can be enabled |
| Document vault | Secure CRM document records are ready | Configure the existing Cloudinary upload credentials, then store the returned secure document URL in the contact vault |
| AI assistant | CRM context and communication records are ready | Provide a production server-side LLM credential and approved model choice before response drafting or summarization is enabled |
| Saved-search alerts | Buyer criteria and delivery preferences are stored | Run the protected alert-processing job after configuring the preferred external delivery provider |

## Running queued follow-ups

The protected endpoint is `POST /api/admin/crm/automation/run`. It processes up to 50 queued CRM follow-ups per run. It accepts either an authenticated administrator/editor session or this header:

```text
Authorization: Bearer <CRON_SECRET>
```

Use a production scheduler to invoke it periodically. The frequency should match your response-time policy; hourly operation is appropriate for standard prospect follow-up, while a daily run may be sufficient during an initial rollout. Avoid enabling the job until `RESEND_API_KEY` and a verified `EMAIL_FROM` address are configured, because email records remain queued when delivery is unavailable.

## WhatsApp and calendar activation

WhatsApp and calendar providers involve account-level authorization, approved business templates, and user consent. Select the provider before implementation and provide its credentials through the production environment. The CRM already respects `whatsappOptIn` for queued WhatsApp content; do not bypass that consent gate.

## AI assistant activation

The assistant should remain server-side and should receive only the CRM context necessary for a requested summary or draft. Before enabling it, choose the provider/model, set a usage budget, and add a human-review step before any external send. The CRM should never automatically send AI-drafted text without agent approval.
